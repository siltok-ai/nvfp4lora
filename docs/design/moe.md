# 混合专家模型

本文说明路由专家怎样流式执行、训练独立 LoRA 并审核优化器状态。

MoE 保留路由和非专家主干在 GPU，路由专家以量化层字节常驻 CPU。专家算子负责原始权重的前向和输入、路由、LoRA 梯度，见[算子实现](../../src/nvfp4lora/ops/experts_fn.py)。

## 专家算子的输入输出

| 对象 | 形状或含义 |
|---|---|
| 输入隐藏状态 | `[T,H]`，计算 dtype 与显式配置一致 |
| 专家索引 | `[T,K]` 的 int64；每 token 选择 K 个专家 |
| 路由权重 | `[T,K]` 的浮点值，参与梯度传播 |
| 六个 LoRA 张量 | gate/up/down 各一个 A 与 B，作为顶层 Tensor 参数传入 |
| 层号与配置 | 非 Tensor 元信息，指定 streamer、块大小及精度 |
| 输出 | `[T,H]`，按原路由槽顺序求和 |

路由计划稳定排序 token 与专家分配。每个块最多解码 `chunk_size` 个专家，零命中专家跳过计算；块大小限制解码与返回梯度的临时工作区。

## 前向和反向怎样使用原字节

1. 按明确层号获取原字节槽，解码当前专家块。
2. gate/up 基座结果与 LoRA 增量在 FP32 参与 SwiGLU。
3. down 基座与增量经路由权重加权，写回每条原路由位置。
4. 反向重新获取层、重新解码，以局部普通 autograd 求本块梯度。
5. 每条路由的输入梯度以 FP32 按 top-k 顺序合并，返回路由权重与六个 LoRA 梯度。

自定义 Function 只支持一阶训练。前向不会保存解码权重供反向使用；冻结专家不参与优化。

## 为什么必须保留路由权重梯度

路由器自身虽冻结，其输入来自可训练主干。若截断路由权重梯度，主干不能收到通过路由分支传播的完整梯度。检查覆盖输入、路由权重和六个 A/B，不能只证明专家 B 有梯度。

小形状普通 autograd、FP64 gradcheck 与非零 B 的对照见[专家测试](../../tests/test_experts.py)和[普通参考](../../src/nvfp4lora/validation/experts_reference.py)。

## 适配器参数怎样组织

每层每专家独立保存 `A[E,r,in]` 和 `B[E,out,r]`，缩放为 `alpha/r`，B 初始化为零。gate/up/down 可各自记录缩放，发布字段不与普通线性 LoRA 混用。

C3 表示非专家的常规注意力投影、GDN 大投影和共享专家三个投影；`expert_rank=0` 仅训练这部分。具体目标正则与预期集合见[构建器](../../src/nvfp4lora/model/build_moe.py)。

## 路由审核检查什么

[`ExpertRouteAudit`](../../src/nvfp4lora/validation/route_audit.py) 只统计原始前向的路由，不重复计入检查点重算。

| 情况 | 判据 |
|---|---|
| 本步未命中专家 | 原始梯度严格为零 |
| 从未命中专家 | 参数和 Adam 矩保持初值／零值 |
| 有历史命中但本步未命中 | 接受标准 Adam 动量更新，记录变化 |
| 保存与恢复 | 保留跨步命中历史，恢复后的检查可继续 |

## 边界

参数组顺序、浮点累积和逐路由写回均属于数值策略。任意专家子集、分层 rank 和融合路由 kernel 尚未提供；方向见[路线图](../../ROADMAP.md)。
