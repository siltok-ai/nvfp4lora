# 有效设计决定

本文记录当前仍约束实现与交付的设计决定。

实现方式和测量数字分别放在设计与结果文档；本页只保留选择理由及重新考虑的条件。

## 运行平台限定为原生 Windows（2026-10-30，用户）
- 背景：目标机器是单张 RTX 5070 Ti 与 64 GB 主存。
- 决定：使用原生 Windows，不使用 WSL。
- 理由：训练环境需与实际交付环境一致。
- 影响：其他平台未测；支持新平台需要独立验证。

## 依赖使用哈希锁和独立环境（2026-10-30，用户）
- 背景：Speed 与训练侧的数值和 ABI 需要可复现。
- 决定：使用[锁文件](../requirements/windows-cu130.lock)及 `--require-hashes`，每个 checkout 单独 venv，不新增或升级依赖。
- 理由：避免共用 editable 和隐式依赖变化造成无法解释的差异。
- 影响：新增 FLA 或其他库必须先批准；环境步骤见[指南](guides/environment.md)。

## 交付核心库与自带脚本（2026-10-30，用户）
- 背景：专用量化执行与完整训练状态需要明确边界。
- 决定：提供核心库和流程 CLI，不引入 DeepSpeed、LLaMA-Factory 或 bitsandbytes；accelerate 仅为 PEFT 传递依赖。
- 理由：以最少依赖交付可核验的训练闭环。
- 影响：接入训练前端属于独立工作，不能跳过现有验证。

## 流式基座保持部署原字节（2026-10-30，用户）
- 背景：训练必须绑定实际部署 checkpoint，完整 BF16 权重超出资源预算。
- 决定：按 revision 和分片哈希绑定来源；流式 NVFP4／FP8 用时解码，反向重新解码，不重新量化或预展开整个基座。
- 理由：保存函数身份并限制内存工作集。
- 影响：常驻张量与流式层的策略分别声明，见[数值设计](design/numerics.md)。

## 缩放位置属于数值接口（2026-10-30，用户）
- 背景：矩阵乘前后施加缩放会产生不同舍入。
- 决定：保留常驻解码、流式码值矩阵乘及 FP32 LoRA 各自的显式顺序。
- 理由：数值相近不等于同表达式逐位一致。
- 影响：修改缩放、GEMM 或精度需重新验证；策略见[数值设计](design/numerics.md)。

## 采用标准 AdamW 动量语义（2026-10-30，用户）
- 背景：本步未命中专家与永久冻结专家不同。
- 决定：AdamW 权重衰减为零，接受默认动量；不抹除本步未命中的历史 Adam 矩。
- 理由：保持标准优化器行为。
- 影响：未命中原始梯度必须为零，但已有动量的参数可以更新，见[路由审核](design/moe.md#路由审核检查什么)。

## 检查点只在完整优化器步保存（2026-10-30，用户）
- 背景：累积中途还存在尚未归并的梯度与执行位置。
- 决定：更新并清梯度后保存参数、优化器、调度器、随机数和数据游标；发布单独输出。
- 理由：恢复边界明确，可以逐位核对。
- 影响：发布不能用于续训；目录与拒绝条件见[状态格式](design/adapters.md)。

## 常规注意力使用展开头后的高效后端（2026-10-30，用户）
- 背景：锁定 Windows 构建的无 mask GQA 会选择 math。
- 决定：两族共用显式展开 KV 的 SDPA 入口，不替换 HF 默认入口。
- 理由：实测输出和梯度误差小于 1%，重复逐位一致，并观测到高效前向、重算和反向。
- 影响：后端与误差需按形状和 mask 复验，见[实测摘要](evidence/current/attention.json)。

## 线性注意力保留纯 Torch 实现（2026-10-30，用户）
- 背景：GDN 是显著计算区间，替换可能需要新增依赖或改变数值。
- 决定：使用锁定 Transformers 的纯 Torch 分块 GDN，不引入 FLA。
- 理由：本次只允许改变常规注意力实现。
- 影响：测量其占比，再由用户决定新的优化实验。

## 密集模型词嵌入保留在 CPU（2026-10-30，用户）
- 背景：GPU 需要容纳流式层、输出头和训练状态。
- 决定：词嵌入表使用普通 CPU 属性，输出头 BF16 常驻 GPU。
- 理由：减少显存占用，并复用分块交叉熵。
- 影响：CPU 查表有 ID 同步代价；布局见[密集模型设计](design/dense.md)。

## 发布与训练权重包保持外部格式（2026-10-30，用户）
- 背景：FreeToken 两个分支正在读取两种发布格式。
- 决定：保留 `nvfp4-lora-v1`、`nvfp4-lora-dense-v1` 及两类 bundle，跨族加载拒绝。
- 理由：消费者接口独立于内部结构整理。
- 影响：格式变更必须单独批准并同步消费者，见[适配器接口](design/adapters.md)。

## 金丝雀由留出和回放共同判定（2026-10-30，用户）
- 背景：学习固定关联时，也要检查已有输出受扰动程度。
- 决定：第 20 步留出至少 45/50，回放 NLL 增量不超过 0.01 nat/token。
- 理由：分别检查适配器学习机制与回放保持能力。
- 影响：只适用于该语料，不是领域质量门槛；确认记录见 [MoE](evidence/moe/threshold-decision.json)和 [dense](evidence/dense/threshold-decision.json)。

## 专家 CPU 参考采用路由拆分判据（2026-10-30，用户）
- 背景：跨精度 top-k 的离散变化会改变被比较的函数。
- 决定：固定 GPU 路由比较前四层，并独立检查同输入的路由投影和权重。
- 理由：区分算子误差与路由边界变化，不将调整后的检查称为无条件通过。
- 影响：同版本续训和发布仍要求逐位一致，见[验证指南](guides/validation.md#专家模型的-cpu-参考怎样判定)。

## 训练不模拟部署激活量化（2026-10-30，用户）
- 背景：训练冻结线性层与部署 W8A8 激活路径不同。
- 决定：保留 FP8 权重原字节与输入缩放，但训练不执行 W8A8 激活量化。
- 理由：明确当前可证明的训练数值范围。
- 影响：范围观测不能替代实际推理和领域评测，见[数值边界](design/numerics.md#与部署推理有什么边界)。

## 正确性由当前代码自行证明（2026-10-30，用户）
- 背景：结构和注意力实现会改变配置身份及训练轨迹。
- 决定：不保持历史哈希或历史探针位；算子、tiny、真实参考、同版本续训及重建分别验证。
- 理由：正确性应依赖参考和闭环证据。
- 影响：跨版本检查点可读不代表精确续训承诺；原始材料保存在归档 tag。

## 模型族以注册表平等接入（2026-10-30，用户）
- 背景：共享训练与存储不应依赖任一模型族。
- 决定：共享代码使用中性模块，族专用实现独立，分派集中于注册表，由分层测试约束。
- 理由：接入新族时增加专用文件与注册记录，无须修改共享流程。
- 影响：字段和扩展入口见[架构](architecture.md#注册表怎样决定模型族)。
